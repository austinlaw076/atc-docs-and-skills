# ATC v1.0.1 correctness and audit contract

Purpose: repair the reproduced v1.0 snapshot alias and validation/deadline bugs, preserve product intent in task delivery, and make criterion and prompt delivery traceable. Audience: trusted host operator, research agents and reviewer. Scope: approved pinned-corpus research only; no new external-action authority or sandbox claim.

Acceptance gates:
1. Caller PRDs, compiled bundles, exported bundle views and dispatch envelopes must not share mutable source/order state with the Coordinator. Source text SHA-256 and derived line arrays must agree before evidence validation. A recomputed outer hash must not excuse inconsistent source data.
2. Untrusted JSON shapes must be bounded before schema work. Cap claims/checks/criteria at64, generic arrays at128, depth16 and traversed nodes8192. Stop collecting validation errors after5; avoid quadratic object uniqueItems checks. Keep 500KB response budget. Pure callback prevalidation yields the event loop. These are bounded local validation controls, not a hard remote-process cancellation guarantee.
3. Recheck the persisted lease after validation and immediately around database-update preparation. A deadline failure rolls back state and removes a newly created unaccepted artifact when possible. Do not accept a late result merely because receive started before expiry. OS fsync/commit latency is not a hard real-time guarantee.
4. Worker and reviewer envelopes include product ID/title/purpose/audience/scope under product_context, bound by input_hash and included verbatim in the persisted prompt.
5. Derive stable local criterion IDs AC001... from each order's acceptance list. Require every reviewer response to cover exactly those IDs, each with satisfied, claim_refs and reason. Satisfied criteria reference existing claims marked supported. The acceptance summary must agree with all criterion decisions. This supplies an auditable judgement, not automatic natural-language entailment or numerical-criterion execution.
6. Persist the exact visible prompt and response-schema hash when dispatching. Bind a true host-returned agent ID, then record an exact-prompt SHA-256 and host receipt ID before receiving results. Missing/mismatched receipts or mutated prompt files must fail validation. Recheck delivery integrity on accepted reports. Receipts are trusted-host attestations, not independently signed proof that a remote model consumed every token or that hidden system context is reproduced.
7. Distinct work orders cannot share a worker identity; retries of the same order may reuse a worker identity. Reviewer identities remain globally role-separated. Separate sessions do not eliminate correlated model errors.
8. Preserve the old v1.0 input PRD format and v0.6–0.9 code/schema history. v1.0.1 compiles to a new contract version and uses *_v1_0_1 schemas; old persisted runs are historical evidence, not silently upgraded. Use a fresh output directory. Review responses and host delivery handoff require the new fields/commands.

Validation: maintain the original45 v1.0 workflow tests, adapting only their explicit unit fixture receipt and criterion structures; add focused regressions for the above gates. Distinguish actual host-agent runs from fixtures. Demonstrate full prompt delivery, per-criterion decisions and dependent tasks through real sessions. Continue to disclose advisory tool restriction until an enforcing runtime is independently tested.
